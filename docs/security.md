## Added controls

- **Least privilege.** The daily job runs as the owner's normal Ubuntu user, not root. It needs outbound HTTPS to the approved sources and Telegram, and write access only to `var/` and the `research/` files it maintains (`research/prereg/`, `research/chain_heads.log`); `config/` is git-versioned and read-only to the job. The MVP opens no inbound port (long polling only later, `## Telegram scope`). Runtime has no MCP and no LLM (agent-design.md `## MCP and integrations`). Any new integration needs owner approval and a read-only scope first.
- **Supply chain.** The dependency set is pandas, pyarrow and pytest, plus the standard library (`## Dependencies`); each licence is still `[Unverified → P1 check: confirm in the project repository]`. Provider client libraries are not dependencies by default and need a supply-chain review first (`## Source adapter boundary`). vnstock 4.0.8 was marked quarantined on PyPI on 2026-09-24 `[Fact: data-sources.md S1]`, so it must not be installed without a review (data-sources.md `## Headline findings` 4). Its licence covers the software, not the data `[Fact: data-sources.md S4]`. Phase 1 rules: pin exact versions in a lock file with hashes `[Assumption: pip hash-checking mode; P1 check against pip docs]`, install only after owner approval, review a new dependency's repository and maintainers before adding it, and never run `curl | sh` or unreviewed install scripts.
- **Paid-API protection.** No paid key is configured and no setting for one exists (`## Configuration and secrets`). If the owner later approves one: a separate key with a provider-side spend limit set at the approved ceiling `[Unverified → P1 check: provider supports hard spend limits]`, a local call counter that stops at a configured maximum per day, and a health signal for usage. Paid data sources follow the same rule (Owner decision 2: zero budget, nothing activated without approval).
- **No trading.** The platform is research and decision support only (CLAUDE.md). No brokerage credential, account number, order endpoint or broker library appears in `config/`, `.env`, or dependencies. `paper` writes hypothetical events to its own ledger and nothing else; `notify` only POSTs a report. Adding any broker integration is a scope change needing explicit owner approval and a new phase.
